📱 Desarrollo Móvil: Creando Aplicaciones

Lectura obligatoria para prepararte para el simulador de AppFlow. Todos usamos aplicaciones móviles (WhatsApp, TikTok, juegos), pero... ¿cómo funcionan exactamente por dentro? ¿Cómo sabe el móvil cuándo tiene que vibrar, hacer una foto o enviar un mensaje?

🤓 Ser Ingeniero de Apps: Crear una aplicación no es magia. Es conectar las piezas lógicas que relacionan lo que ocurre en el mundo exterior con las acciones que el teléfono debe realizar.

1. Programación Orientada a Eventos

La mayoría de programas que hemos hecho hasta ahora (como en Scratch o Code.org) siguen una secuencia: el código se ejecuta línea por línea de principio a fin. Sin embargo, las aplicaciones móviles usan un sistema diferente llamado Programación Orientada a Eventos.

En este sistema, el programa se queda "esperando" (dormido) a que suceda algo. Ese "algo" que sucede se llama Evento.

🔌

1. El Sensor (Input)

Es el hardware o la pantalla que recoge el estímulo externo. Ejemplo: El cristal táctil, el GPS, la cámara, el acelerómetro.

⚡

2. El Evento (Disparador)

Es la interpretación del estímulo. Ejemplo: "El usuario ha hecho click", "El móvil se está agitando", "La luz ha bajado del 10%".

🚀

3. La Acción (Output)

La respuesta programada de la app. Ejemplo: Enviar notificación, encender la linterna, guardar la foto o reproducir un sonido.

2. Front-End y Back-End

Cuando un desarrollador crea una app móvil, tiene que trabajar en dos mundos completamente distintos:

  • 🎨 Front-End (Interfaz de Usuario o UI): Es todo lo que ves y tocas. El color de los botones, el tamaño del texto, las animaciones y dónde está cada menú. Está pensado para que la aplicación sea fácil y agradable de usar (UX - Experiencia de Usuario).
  • ⚙️ Back-End (Lógica Oculta): Es el código que funciona por detrás. Se encarga de guardar los datos en la base de datos, comprobar tu contraseña, comunicarse con los sensores (GPS, cámara) y procesar eventos lógicos. ¡Aquí es donde jugarás en AppFlow!

3. Tipos de Aplicaciones

No todas las apps de tu móvil están fabricadas igual. Existen diferentes enfoques:

  • 📱 App Nativa: Programada específicamente para Android (ej. en lenguaje Kotlin) o para iPhone (ej. en lenguaje Swift). Funcionan rapidísimo y tienen acceso total a los sensores físicos.
  • 🌐 Web App: Es una página web diseñada para verse perfecta en móvil. No se instala desde la tienda (Play Store), se entra desde Chrome o Safari. No puede usar sensores avanzados y necesita Internet, pero no ocupa espacio.
  • 🏗️ App Híbrida: Es un intermedio. Se programa una sola vez (usando tecnologías web como HTML y JavaScript) y luego se empaqueta como si fuera una app nativa para instalarla.

4. ¿Cómo piensa la App? (Lógica Condicional)

A veces un evento no es suficiente para lanzar una acción. Imagina que el móvil detecta que has entrado a tu instituto (Sensor GPS → Evento "Llegar") y la acción programada es "Poner el móvil en silencio". ¿Pero qué pasa si es sábado por la tarde y has ido a las pistas de baloncesto? ¡No quieres que se ponga en silencio!

Por eso los desarrolladores usan Condiciones Lógicas (Filtros), que actúan como "porteros de discoteca".

🧠 Regla lógica de AppFlow:
GPS (Llegar al IES) ➡️ [SI es lunes a viernes a las 08:15] ➡️ Activar Modo Silencio.

📝 Resumen para AppFlow

Lo que vas a necesitar en el simulador:

  1. Lee el encargo: Fíjate bien en qué te pide el cliente. ¿Necesita sonido? ¿Linterna? ¿NFC?
  2. Identifica el Sensor (Input): ¿Qué hardware va a captar la acción inicial del usuario? (Cámara, GPS, Botón, Giroscopio).
  3. Identifica el Evento: ¿Bajo qué circunstancia se activa ese sensor? (Ruido fuerte, Al agitar, Oscuridad).
  4. Identifica la Condición (Si la hay): Busca palabras clave como "Solo si...", "Y además...", "Pero solo cuando...".
  5. Conecta la Acción (Output): Termina la cadena decidiendo qué debe hacer el teléfono.
